# W22-02: Rozwiązywanie workflowu bez runtime MCP

Status: planned — Gate 1 pending.
Feature: [brief](../docs/features/F-W22-hcom-native/brief.md).
Design: [plan](../docs/features/F-W22-hcom-native/design.md).
Dependencies: W22-01.
Format: Markdown work-items; Yumi CLI nieobecne.

## Wynik i zakres

Wdrożyć rozróżnienie nowego i legacy trybu w source reader/resolve/begin/adopt/switch. Nowe repo domyślnie standalone hcom bez dodatkowej flagi; zmigrowane repo może zachować stare archiwum bez wymagania starego runtime. Nie omijać nieukończonej migracji ani błędnej konfiguracji. Zachować identity istniejącego locka, restore dokładnej wersji, udowodnione legacy i jawny wybór przy niejednoznaczności. Nie zmieniać żadnej zainstalowanej paczki w miejscu.

Punkty startowe: scripts/workflow-source/select-source.mjs, workflow.mjs, workflow-lib.mjs; tests/test_workflow_entries.py, test_workflow_bundle.py.

## Odbiór i dowody

Pokrycie: AC-01, AC-05, AC-07.
Fixtures: świeże repo, po migracji z archiwum i brakującym runtime, stary/nowy/poprawny/uszkodzony/brakujący lock, brak bundle, pending marker, invalid marker, jawny legacy. Brak wywołań MCP i importu runtime w nowej ścieżce; znane legacy zachowuje dotychczasowe refusal.

Ledger podczas wykonania: `docs/features/F-W22-hcom-native/execution/W22-02/01.md`.
