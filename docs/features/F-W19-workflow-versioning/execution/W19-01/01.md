## Problems and resolutions

- Ustalenia prób, które ukształtowały kontrakt (§ 11): po `--resume`/`exec resume` ta sama sesja
  pokazuje nową treść wejścia, ale stara zostaje w historii; lista skilli Claude’a po resume jest
  historią przyrostów i w przypadku D wskazywała 3.0.0, choć aktywna była 2.0.0
  (`resume_listing_tail_matches_active_package: false`). Rozwiązanie: rundy i manager potwierdzają
  identity jawnie (`workflow_identity` w run, blok WORKFLOW w prompcie, odczyt z ROOT), a lista
  skilli nie jest dowodem.
- Codex po aktualizacji usuwa katalog cache starej wersji, do którego odwołuje się historia;
  marketplace katalogowy Claude’a serwuje z folderu źródłowego, nie z cache → identity zawsze
  z `bundle/` własnej paczki, praca z magazynu niezależnego od cache.
- Blok MCP setupu przekazuje tylko `CLAUDE_CODEX_BRIDGE_HOME`/`XDG_DATA_HOME`; serwer MCP
  uruchomiony przez Codex nie dostaje `CLAUDE_CONFIG_DIR` → delegowany Claude w pilocie
  użyłby profilu osobistego. Zapisane jako warunek PILOT-ENV-01; dodanie zmiennej do `env_vars`
  sprawdzone w próbie E.
- Stare runtime’y 0.6.x/0.7.0 mają `plugins/feature-workflow-*`, ale ich preambuła kieruje do
  bieżącego pina; legacy bundle bierze więc kanoniczne pliki z manifestu runtime’u i adapter.
- Własne poprawki w trakcie: weryfikacja `workflow_id` dodana do `verify_bundle`; fixture kolizji
  magazynu przerobiona na realny przypadek (inny ważny bundle pod tą nazwą); mutacje negatywnych
  fixture’ów aktualizują `workflow_id`, aby trafiać w zamierzony kod; zastąpienie natywnych ID
  sesji w dowodzie skrótem. Wszystko przed finalnymi kontrolami.

## Deviations and proposals

Normalne wybory w granicach design: nazwy operacji (`bridge_workflow_*`, `workflow.mjs`),
`workflow_id = <version>-<12 hex>`, identity bez `source`, draft `.draft-<token>`, capabilities v1,
`reload_mode = reread | restart-resume`, ack identity jako parametr `bridge_feature_run`,
legacy bundle z plików manifestu runtime’u przez `legacy-adapter/v1`, tabela profili legacy
w runtime’ie. Propozycja dla koordynatora (publiczne API przed konsumentami): dodanie
`workflow_identity` do `bridge_feature_run` i opcjonalnego `workflow` do `bridge_feature_create`.
Brak dowodu wymagającego zmiany AC; nie ma blokady zależnych tasków.
