## Problems and resolutions — R03 dispositions

**R03-01 — native manager identity: resolved (within the boundary decision 06 set).**
Revision 2's model (advisory id, user-held token, "no verified channel") is **removed from the
contract**, not annotated. §5 defines the envelope read from `RequestHandlerExtra._meta` and
captured once per call — explicitly *not* a global last-request variable — with a full
classification table (missing, non-object, malformed, subagent, inconsistent ids, absent turn
metadata, `thread_source` present) and the rule that arguments are never a source or fallback.
§7 gives the transition table: unbound + valid root + valid operation → bind at epoch 1 together
with the operation; unbound + invalid operation → whole transaction rolls back and the worktree
stays unbound (no partial takeover); two concurrent roots → `BEGIN IMMEDIATE` yields exactly one
winner and the loser gets `MANAGER_FOREIGN_THREAD`. §9 separates the guarantee (accidental mixup
of correctly functioning local sessions) from what is not promised (a same-UID process forging the
host envelope). Guardian exclusion rests on host evidence (`reviewer_config.rs:67-73`), not on a
differing thread id.

**R03-01 point 3 — resume, instances, takeover: resolved.** §7 binds authority to the *thread*,
not the process: resume keeps the thread id (`session.rs:761-797`), so an MCP restart needs no
re-attach, no token and no epoch change, and two live instances of the same thread are two
channels of one manager whose writes serialise in SQLite — which removes fencing ping-pong by
construction instead of arbitrating it. A different thread is denied and must use
`bridge_manager_takeover` (CAS on thread + epoch, with reason and history); after a takeover the
old thread can never regain ownership through an ordinary mutator (`MANAGER_FENCED`). A running
round is never cancelled or silently restarted. No tokens exist anywhere in the contract.

**R03-02 — read/mutation classification: resolved.** The r2 contradiction (a tool declared
write-free that wrote for the owner) is gone: each tool now has exactly one branch. §6 defines
classes R/O/M/T/I; `bridge_feature_get` and `bridge_recover` are pure for *every* caller, and
reconcile/reap run only inside a Class M/O transaction after the guard. §6.3 fixes the single
transactional boundary (re-read binding → compare captured native context → reconcile/reap →
operation writes → events, rollback on any failure), with asynchronous operations guarded at the
existing reservation points. Crucially, §1.1 and §4.2–4.4 now account for the **constructor**
writes the review named: `sqlite-store.ts:226-246` creates the file, sets the journal pragma, runs
DDL/migration and upserts `schema_meta` (`240-245`) on every open. Startup therefore performs *no*
writes at all, reads go through a new `openReadOnly` path, and `openForWrite` is reachable only
from the authorized bootstrap. Test B-05 asserts byte-identity across start, handshake,
`tools/list` and all reads, explicitly covering DDL/`schema_meta`/journal and not just boot reap.

**R03-03 — one atomically reserved database per worktree: resolved.** The review's counterexample
(two processes, one fresh worktree, two `--db`, marker `database = null`) is closed by making the
marker's `database` field part of its atomic creation — there is no `null` phase, so the
`linkSync` race picks one winner before any database file exists (test D-01). The
two-worktrees/one-database race is closed differently and more strongly: §3 requires the database
to resolve inside this worktree's own `.bridge/`, compared after `realpath`, so a shared or
external database is refused before any open (test D-02). Consequently record **B (the external
sidecar) is removed**, which also resolves its two r2 contradictions (a write outside `.bridge/`
in a step that forbade them, and "C overrides B" versus refusing before C was read); §4.1 records
this explicitly rather than silently dropping it. Marker loss is now handled honestly: if the
requested database holds a matching binding row, the marker is **reconstructed with the same
`workspace_id`** (never a new one, which was the r2 lock-out bug); if no database can be located,
the result is fail-closed `unresolved_workspace_state` with no scanning, guessing or deletion
(test D-03). Mid-bootstrap crashes are tabulated in §4.5, including the schema-only rolled-back
file, which binds as "empty" (test D-04).

**R03-04 — archive limitation and external database: resolved.** Because §3 keeps the database
inside `.bridge/`, the archive-by-rename remedy is now self-contained; the r2 hole where an
external `--db` stayed bound to the old path cannot arise, and §4.6 states the restriction and its
reason. The instruction additionally requires the archive to be moved **outside the repository**,
precisely because `.bridge.moved-*` is not matched by the existing `.bridge/` ignore rule and
would otherwise risk committing runtime metadata. No rebind, installer or diagnose command is
added.

**Decision 06 §7 — stale claims removed: done.** The contract no longer contains
"no verified native source", advisory-only native id, manual tokens/custody, the user-as-custodian
restart procedure, `bridge_manager_claim`/`attach`/`release`, or the Q-02 alternatives; §16 lists
the withdrawals. Historical ledgers, reviews and decisions keep their original text.
