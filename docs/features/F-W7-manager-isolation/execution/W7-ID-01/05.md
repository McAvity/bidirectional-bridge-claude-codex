## Problems and resolutions — R05 dispositions

**R05-01 — persistent exclusive-create lock cannot recover after a crash: resolved.** The `wx`
`state.lock` pathname is withdrawn: an O_EXCL name is not released by process death, so both the
stale-reservation path and the crash-after-commit path were unrecoverable. The critical section is
now a `BEGIN IMMEDIATE` transaction on `<root>/.bridge/state.lockdb` (contract §4.1, §4.4 step 2),
chosen because its mechanism and lifetime are **established by the reproduction above**, not
assumed: exactly one live holder, contenders get `SQLITE_BUSY`, and the kernel releases the lock on
process death. It uses technology already in the control plane (`BEGIN IMMEDIATE` with
`busy_timeout`), adds no dependency, no product code and no installer, and never inspects PIDs or
mtimes. §4.5 now gives a deterministic outcome for every crash boundary: death before publication,
death after publication but before the database commit, death after commit but before the rename,
and partial A/B publication in both directions. Critically, **recovery happens only during an
authorized ownership mutation**: revision 4's "next start completes the rename" is withdrawn
because it contradicted startup/read write-freedom, so startup and Class R calls now only *report*
`marker_incomplete`/`recoverable` (§4.3), and the rename is completed inside the critical section
by the manager that record C names. Re-reading C with an existing binding rewrites A/B only — it
never recreates `epoch 1` or a history row, and a foreign caller is denied and leaves A/B
untouched. Tests L-01…L-05 cover contention, both death points, the report-only property and
partial publication.

**R05-02 — fresh bootstrap invalidated its own empty-directory preflight: resolved.** The order is
now explicit (§4.4): read-only preflight with **no `mkdir`** → `mkdirSync(.bridge, {recursive})`
as the first durable write of the authorized path (needed because `wx`/`link` cannot create a
missing parent) → acquire the critical section → **re-classify with a self-artefact exemption**.
The exemption names exactly what this operation created or holds — `.bridge/` itself, the lock
database and its sidecars, and `*.tmp` files carrying this operation's nonce — plus entries
explained by the requested database and a matching marker; **anything else**, including another
`*.db`, another `*.owner` or an unparsable marker, remains fail-closed
`unresolved_workspace_state`. So a missing or empty `.bridge/` bootstraps, unknown prior state
still refuses, and the protocol's own infrastructure can no longer make a legitimate fresh
bootstrap refuse itself (test L-06). Resolved jointly with R05-01, as the review required.

**R05-03 — precheck did not authorize later migration through takeover: resolved.** The
counterexample is accepted as valid and revision 4's claim that the precheck window was safe is
withdrawn as false. §6.3 now states one rule: **every DDL, migration, `schema_meta` and
journal-mode write happens inside the same serialized, authority-validated boundary as the
operation that needs it — never before it.** Concretely, bootstrap, migration of an existing
database, takeover and handoff all take the critical section *and* run their authority check
inside the main-database `BEGIN IMMEDIATE`, with DDL and `schema_meta` executed in that same
transaction so a denial rolls them back; journal mode is set only while an authorized
initialization creates a new file, and `attachExisting` **never** changes persistent journal mode
or upserts `schema_meta` even when the current mode differs (§6.2), which closes the conditional
journal rewrite the review flagged. Because Class T and Class H also take the critical section, I1
cannot migrate while I2 takes over: one waits for the other, and the loser re-reads the binding on
entry and is refused before any durable write. The precheck is now described as a fast refusal
filter that authorizes nothing. Tests M-01 (deterministic pause after precheck + takeover, then
assert zero schema/journal change), M-02 and M-03 cover this.

**R05-04 — instance resume ABA and reactivation of fenced instances: resolved.** Class H now
requires **`expected_epoch` *and* `expected_generation`** in one CAS together with the host-proved
thread (§7.1); because epochs are monotonic and never reused, the delayed H from
T1/generation 1 that revision 4 would have accepted after T1 → T2 → T1 is rejected. Automatic
adoption is no longer unconditional on `active_instance_id IS NULL`: it is limited to an instance
whose `instance_id` has **no row in `manager_instances` for the current epoch**, enforced by a new
unique index on `(epoch, instance_id)`. A fresh process always qualifies, so the tokenless restart
after a clean detach still works, while the fenced I1 of the review's sequence (H to I2, I2
detaches, ordinary M from I1) is refused and must use an explicit Class H. The transition table
also qualifies the post-takeover row as the review asked: Class R from the old thread remains
allowed, Class M/H are `MANAGER_FENCED`, and an explicit Class T with the current `(thread, epoch)`
and a reason remains the way to regain authority. Interface, SQL, transitions and tests
(I-01…I-06) are aligned.

**R05-05 — only 0.154.0 is verified: resolved.** §5.3 narrows the allowlist from `0.154.*` to
exactly `codex_version == "0.154.0"`, with `adapter_id = "codex-0.154.0"`; any other version,
including an unknown patch such as `0.154.1`, is `native_adapter_unsupported` until verified and
added explicitly. The open-items list and this ledger use the same exact version, and test A-01
asserts the allowlist boundary and the recorded adapter id. No launcher or further host-version
investigation was performed, as the review directed.

## Deviations and proposals

No requirement was weakened and no new user decision was needed; all five findings were resolved
inside `decisions/06.md`. The design choices that go beyond prose are the SQLite-based critical
section (justified by reproduction rather than by assertion), the self-artefact exemption list,
moving every schema-affecting write inside the authority-validated transaction, the
`(epoch, generation)` CAS with history-based adoption eligibility, and the single-version adapter
allowlist. One honest limitation is added rather than hidden: on filesystems where POSIX advisory
locking does not work, the critical section degrades and the protocol fails closed with
`state_locked` instead of proceeding. Files outside `contracts/**` and `execution/W7-ID-01/**`
were not modified.
