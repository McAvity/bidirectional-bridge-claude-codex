## Problems and resolutions — R04 dispositions

**R04-01 — envelope fail-open: resolved.** Both fail-open paths are closed. §5.2 now **rejects** a
call whose `x-codex-turn-metadata` object is absent (`native_context_incomplete`) — that object is
precisely what subagent classification depends on — and requires `session_id`, `thread_id`,
`_meta.threadId` to be present and mutually consistent. §5.3 replaces the `strict-fallback`
escape: `codex_version` is mandatory and must match a verified adapter, with exactly one defined
(`codex-0.154`, the version whose envelope *and* guardian behaviour were verified); any other
version is `native_adapter_unsupported` until an adapter is added with its own verification.
`NativeCallContext` now types `session_id`, `meta_thread_id`, `codex_version` and `adapter_id` as
required, `thread_source` stays optional (a legitimate root was observed without it), and
`native_corroboration` can no longer be `none` for accepted ownership — the SQL carries a
`CHECK (native_corroboration = 'turn-metadata')`, and test E-01/E-04 assert both. No
interactive-CLI requirement was invented: §9.4 now states that a second root such as `codex exec`
is a different root rather than a guardian bypass, and that an interactivity flag could not choose
between two roots either.

**R04-02 — instances and fencing: resolved.** Revision 3's "any instance of the thread may mutate"
is withdrawn. Authorisation again requires **both** the host-proved thread and
`active_instance_id` + `instance_generation` (§7); a non-active instance's ordinary mutator is
denied with `MANAGER_INSTANCE_FENCED`, so no ordinary traffic can ping-pong authority. Switching
connections is possible only through the explicit, **tokenless** Class H
`bridge_manager_resume_instance`, whose authority comes from the host context (identity), with
`expected_generation` used purely as concurrency control — the contract states explicitly that CAS
parameters are not identity proof. Clean detach clears `active_instance_id` so an ordinary restart
is adopted automatically; after a crash the replacement makes one explicit Class H call, with no
liveness guessing; a fenced instance can never restore itself through a mutator. Two simultaneous
resumes are covered: first wins, second refused on the generation and must re-read status. SQL
gains `manager_instances` history plus the two current fields, and tests I-01…I-04 cover detach,
crash, double resume with a no-ping-pong loop, and takeover.

**R04-03 — external `--db` and the symlink rule: resolved.** The r3 removal of explicit external
`--db` was unauthorised and is withdrawn; the claim that the user had requested it is gone. §3
restores it and replaces the broken predicate. The review's counterexample is decisive: with both
worktrees symlinking `.bridge` to one directory `S`,
`realpath(parent(db)) == realpath(root/.bridge) == S` holds for both, so path equality would admit
shared state; exclusivity is therefore decided by **recorded identity** — marker A, database owner
file B (`<database>.owner`, beside the database wherever it lives) and binding row C each record
`workspace_id` and root, and the question asked is "does this state claim *this* worktree?".
Two invariants are stated: one database per worktree (A, C) and one worktree per database (B, C).
Canonicalisation is kept only for *finding* artefacts through symlinks, never as proof;
`resolveDatabasePath` canonicalises via the nearest existing ancestor so a fresh default path
resolves during a read **without creating `.bridge/`** (test D-06). The archiving limitation
decision 06 §6 asked for is now described rather than legislated away (§4.6): an external database
does not travel with a `.bridge` archive, so a fresh start at a new path needs a new `--db` while
the old external database and its `.owner` stay intact. Tests D-02, D-03 cover the shared-symlink
case and external-DB support.

**R04-04 — reservation, marker loss and crashes: resolved.** §4.4 fixes one order — preflight
(read-only) → worktree state lock → recheck under the lock → publish reservation A and B →
guarded open → single transaction → publish completion — so nothing durable is published before
the preflight that justifies it, and the r3 inversion (creating A with a new `workspace_id` before
reading C) is gone. §4.5 tabulates the rest. Crash after commit before rename leaves `reserving`
alongside a real binding, so resolution is driven by C and the contract explicitly **never advises
deleting a `reserving` marker** — that state is indistinguishable from a live bootstrap by
inspection. A stale reservation without C may be superseded only on evidence (read-only probe
shows no binding row and A/B are not `bound`), and a surviving original aborts at the
**reservation-nonce re-check inside the commit transaction**, which is what prevents two databases
bound to one worktree without any liveness guess. A failed first operation rolls back and the
process releases **its own** nonce-identified reservation, so a technical reservation never becomes
a silent permanent database change. The undetectable case is now concrete rather than promised:
marker absent + requested database absent + non-empty state directory → fail closed
(`unresolved_workspace_state`) without choosing a database and without scanning for bindings;
reconstruction from C with the same `workspace_id` happens only when C is actually present in the
requested database.

**R04-05 — opening before the guard, and read semantics: resolved.** §6.2 splits store opening
into `openReadOnly`, `attachExisting` (read-write, no DDL, no migration, no `schema_meta` upsert,
refuses a newer schema) and `initializeOrMigrate` (today's constructor behaviour). §6.3 fixes the
order for every class: a **read-only precheck** decides refusals first, so a foreign thread,
fenced instance, unsupported adapter or foreign database is denied having opened nothing for
write — closing the r3 hole where the writing constructor ran before the manager guard and could
write DDL/`schema_meta`/journal state. Write-open happens only for a caller the precheck did not
refuse; the authoritative check is then repeated inside the `BEGIN IMMEDIATE` transaction, so a
takeover landing between precheck and transaction causes a rollback rather than an unauthorised
write. Takeover explicitly never runs DDL or migration, and the restart path for an already-bound
database is the concrete `attachExisting` route that r3 lacked. The false physical guarantee is
replaced by an honest one (§6.4, from this round's reproduction): reads guarantee no durable state
or ownership mutation — no marker, owner file, lock, binding, schema, `schema_meta`, migration,
reconcile, reap, rows or events — while SQLite may create `-wal`/`-shm` technical sidecars beside
an existing database; `immutable=1` is rejected because it would ignore a live WAL and serve stale
data; and the absolute "creates nothing" promise is kept only where it is true, namely when the
database does not exist. Tests B-05 and B-06 assert exactly these properties.
