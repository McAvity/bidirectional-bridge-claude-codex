## Finding-by-finding

**R08-01 (blocking) — real guard inside asynchronous reservations: fixed.**
`DelegateOptions.authorize` and a new `RecoveryOptions.authorize` are invoked *inside* the
reservation transactions — `Orchestrator.delegate` before `tasks.create`, `prepareRecovery` before
any attempt/lease/event write — and `FeatureWorkflow.run` forwards the same closure. The tool layer
passes it down for the four named async operations. In an unbound worktree the closure itself
writes the manager binding and `workspace_binding`, so an invalid first asynchronous operation
rolls the ownership back with the reservation. `runMutationAsync` additionally refuses to report
success if the guard was never executed. Test: a gated fixture round, a takeover committed while
the worker runs, then the fenced manager's next `bridge_feature_run` denied with no new task
(`identity-guard.test.ts`).

**R08-02 (blocking) — transactional schema initialization/migration: fixed.**
`SqliteStateStore` gained `initializeSchema()`, which runs DDL, migration and the `schema_meta`
upsert inside one transaction, plus `ensureJournalMode()` used only for a database this process
just created and a refusal for a newer schema on attach. The identity path now opens `attach`
(no schema writes) and calls `initializeSchema()` **from inside the authorize closure**, after the
authority decision. Test: a bound database downgraded to `schema_version = 4`; a foreign caller is
denied and the version stays 4; the owning session resumes its instance and the same call migrates
to 5.

**R08-03 (blocking) — read projection without replacing the writer: fixed.**
`ControlPlane` keeps a separate read-only projection; `activate("readonly")` never closes or
replaces a live writer, and reads fall back to the writer when a round holds it. Test: status,
snapshot and feature reads during a gated round, after which the worker still completes, its
deliverable is recorded and its lease is released.

**R08-04 (required) — §8 launch/recovery prohibition: fixed.**
`LAUNCH_OPERATIONS` names `bridge_delegate`, `bridge_feature_run`, `bridge_resume_task` and
`bridge_resume_delegated_task`; a non-`codex` role is refused for exactly those before any side
effect, while its own task writes without Codex metadata keep working. The test asserts the
permitted write first, so the refusal cannot be an artefact of another rule.

**R08-05 (required) — legacy adoption and feature isolation: implemented.**
`--adopt-legacy-state` with a mandatory `--adopt-reason` (1–500 chars, rejected on its own) binds
an unbound legacy database and records provenance in `workspace_binding.adoption_json` plus a
`workspace.adopted` event, surfaced by `bridge_manager_status`. Features now carry `workspace_id`,
`manager_epoch` and `round_launches`; `bridge_feature_create` claims the worktree's single feature
slot (`FEATURE_CONFLICT` otherwise) and `bridge_feature_accept` frees it; `bridge_feature_run`
claims the slot inside its reservation and attributes the round to the launching thread/epoch.

**R08-06 (required) — detach bumps the generation and records the event: fixed.**
`ManagerRegistry.detach` ends the activation row, increments `instance_generation`, writes the
binding and appends `manager.detached` exactly once; a repeated or stale call is a no-op. Test: a
handoff CAS captured before a clean shutdown is refused afterwards, while a fresh connection still
adopts the detached binding.

**R08-07 (blocking) — publication/crash protocol: fixed.**
`publishReservation` now takes the under-lock probe and returns the nonce in force: it supersedes
an interrupted `reserving` record, fails closed on a record claiming `bound` without a binding row,
and no longer EEXIST-refuses its own recoverable state. Bootstrap settlement is decided by what
actually committed — a binding row completes the publication, its absence releases only this
attempt's own reservation — so a post-commit failure can no longer withdraw committed state.
`assertProbeUsable` now compares A and B against C (workspace id, database path and, for `bound`
records, the reservation nonce) and refuses contradictions instead of repairing them. Temp-file
recognition is restricted to the two protocol basenames with a complete, well-formed record
including `git_dir`. Tests cover an interrupted publication that a later bootstrap completes with a
fresh nonce, plus partial/foreign/malformed records.

**R08-08 (required) — coverage through real entrypoints: extended.**
Seven new tests in `identity-guard.test.ts` drive the public tool surface with real Git worktrees
and real SQLite, next to the existing 20 identity tests. Total suite: **369 tests in 25 files**
(was 362/24). The compatibility mode is unchanged in behaviour but is now explicit: identity is
enforced whenever a server is constructed with a canonical `workspace`, which the production
launcher always passes; the injected-store path used by unit tests cannot be reached through the
public MCP surface.

**R08-09 — out of scope, still open.** Not touched, as instructed: the operator dry-run file was
neither edited nor inspected, and production metadata enforcement was not weakened.
