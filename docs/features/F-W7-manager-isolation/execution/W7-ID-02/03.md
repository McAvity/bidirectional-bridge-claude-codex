## Finding-by-finding

**R09-01 — no reconcile before authority.** `FeatureWorkflow.run` now takes its preflight from the
pure `view()` instead of the mutating `get()`, so a foreign or fenced caller can no longer
reconcile the feature or append `FEATURE_UPDATED` before being refused. Round attribution is no
longer copied from the preflight: `RoundRequest.attribution` became a resolver invoked inside the
reservation transaction, after the guard, reading the epoch and thread from the binding itself.
Regression: a completed-but-unreconciled feature, a foreign `bridge_feature_run`, and an assertion
that the feature rows and `last_event_id` are byte-for-byte unchanged.

**R09-02 — authorized replay no longer produces INTERNAL.** The fabricated "guard never ran"
internal error is gone. Asynchronous operations are authorised twice: once at dispatch (in its own
transaction, for the already-bound case) so a legitimate replay that reserves nothing is still
checked against current ownership, and once inside the reservation transaction when a reservation
actually happens. Regression: an owner replay of a completed round returns the same task with
`replayed: true` and launches nothing, while a foreign replay of the same key is refused with
`MANAGER_FOREIGN_THREAD` and still launches nothing.

**R09-03 — handoff/takeover repair only after their CAS.** For Class H/T the guard now performs no
write at all: `authorize` returns the current binding, the handler executes the real CAS, and
marker repair moved to `afterOperation`, which runs inside the same transaction only after the CAS
succeeded. H/T never migrate; they are refused only when the ownership tables do not exist yet
(which would make a CAS impossible), so a fenced manager on an older schema is not deadlocked.
Regression reproduces the coordinator's case — bootstrap, delete `bridge.db.owner`, foreign
handoff — and asserts the owner file is **not** recreated; a stale takeover likewise repairs
nothing, and the owner's authorized mutation does repair it. I verified this is a real red→green
fix by temporarily restoring the old ordering: the test fails (owner file recreated) and passes
again after restoring the fix.

**R09-04 — the feature slot covers every mutating touch.** `claimFeatureSlot` runs inside the
guarded transaction for `feature_create`, `feature_run`, `feature_wait_user`, `feature_answer_user`
and `feature_accept`; an adopted historical feature claims the empty slot on its first touch, and
`accept` releases only its own feature. Reads stay pure. Regression: with `F-one` active, the
create/question/answer/accept of `F-two` are each refused with `FEATURE_CONFLICT` and the durable
state is unchanged. Adoption provenance now records per-table row counts in the binding row and the
`workspace.adopted` event.

**R09-05 — schema initialization inside the reserving transaction.** `initializeSchema()` moved
from before the body into the bootstrap `authorize` closure, so it joins the operation's
transaction and rolls back with it; only the journal mode of a genuinely new file is set outside a
transaction, under the lock, and an existing journal mode is never rewritten. Regression uses a
real historical fixture — pre-isolation tables only, `schema_version = 4`, with history — and a
first authorized operation that fails: afterwards the schema is still 4, there is no binding, no
marker, and the database file length is unchanged; a subsequent valid operation adopts it and
records provenance.

**R09-06 — critical-section lifecycle.** Release is now exactly once, through a shared
`releaseOnce` guard, and publication happens at the reservation boundary: `DelegateOptions` and
`RecoveryOptions` gained `onReserved`, called after the reservation transaction commits and before
the runtime is invoked, and `FeatureWorkflow.run` forwards it. The double release (`result.finally`
plus the synchronous `finally`) that could reject an otherwise successful async result is gone.
Regression: an asynchronous first ownership call with a gated worker — while the worker runs, both
markers already read `bound` and another process can acquire the worktree lock; the round then
completes successfully.

**R09-07 — deterministic coverage.** Seven new regressions in `identity-recovery.test.ts`, one per
finding, plus the missing two-worktree `waiting_user` restart: pair A asks a question, its manager
process detaches cleanly, pair B runs its own round in its own worktree, and pair A restarts,
keeps the question, answers it and resumes **the exact fixture worker session** (`resume_required`
with `previous_execution_handle: "session-A"`), with every invocation confined to its own
`workspace_root`.

## Limitations

1. The package manifest legitimately reports `worktree_dirty: true`: the coordinator snapshot
   listed above is present and uncommitted by design. No all-clean claim is made.
2. Handoff/takeover against a database whose ownership tables are missing are refused rather than
   migrating; the operator performs an authorized mutation first.
3. Round attribution resolves from the binding inside the reservation; if a takeover commits
   between the guard and the attribution read within the same transaction it cannot change, but
   attribution for a *replayed* round is not rewritten.
4. All adapters and host envelopes in tests are synthetic fixtures. No live two-model pilot is
   claimed, and the contract's documented limits (host 0.154.0, local advisory locking, no defence
   against a forged same-UID envelope) stand.
