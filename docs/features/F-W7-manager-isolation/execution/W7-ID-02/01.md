## Limitations and deviations

1. **Open regression, out of scope.** The operator dry-run must attach a native envelope
   (`params._meta`) like the updated stdio tests do. The fix is a few lines in
   `tools/pilot/rework/operator/dryrun.mjs`, which this round may not edit. Nothing was weakened
   to make the suite green.
2. **Enforcement is bound to the product composition root.** `BridgeMcpServer` enforces identity
   only when constructed with a canonical `workspace`, which the native launcher always passes.
   Embedders and unit tests that construct a plane without it keep the pre-isolation behaviour;
   this is what the contract's §10 foresees, and it is why the existing 342 tests still pass.
3. **Asynchronous mutators are guarded before the work, not inside the reservation.**
   `bridge_delegate`, `bridge_feature_run` and both resume tools authorise in their own
   transaction and then run outside it, because a SQLite transaction is synchronous. Contract
   §6.3 wants the check inside the orchestrator's reservation hook; that wiring is **not
   implemented**, so a takeover committing between the guard and the reservation is still
   possible for those four tools. This is the main known gap against the contract.
4. **Schema migration of an existing bound database** uses `initialize` inside the critical
   section, but no test exercises an actual schema-4 → schema-5 upgrade of a *bound* database;
   legacy databases with history are refused, which is tested.
5. **Not implemented in this round**: `--adopt-legacy-state` / `--adopt-reason` (§10 explicit
   adoption), one-active-feature enforcement wiring for `bridge_feature_*` (the registry has
   `claimFeature`/`releaseFeature`, but the feature tools do not call it yet), and the
   `bridge_manager_status` `resume_hint`.
6. **No live pilot.** Every native envelope in the tests is a synthetic fixture. No test here is
   evidence of two live model pairs, and the stdio tests drive the real launcher with a fixture
   client, not Codex.
