## Finding-by-finding

**R10-01 — asynchronous finalization repairs markers before the lock is released.** An async body
returns at the reservation boundary and never reaches `afterOperation`, so a valid
delegate/feature_run/recovery on a worktree with incomplete markers left them incomplete. Repair is
now also performed in `settle()`, which runs at that boundary while the lock is still held: it
re-checks authority purely, rewrites only the marker and owner files, and is skipped entirely on
the failure path. If authority changed between reservation and settle, the repair is deliberately
skipped and left to the next authorized mutation rather than performed for a session that no
longer owns the worktree. Regression: bound worktree with a `reserving` marker and a deleted owner
file, gated fixture worker — at worker start both records read `bound`, the critical section is
free, the round completes, and the binding, epoch count and activation count are unchanged.

**R10-02 — the dispatch-time check is pure.** `ManagerRegistry.assertAuthorityPure` answers the
same questions as `authorizeMutation` (owning thread, permitted connection, adoptable fresh
instance) while writing nothing, and the async dispatch now calls it instead of the mutating
`authorize`. Adoption and migration happen only inside the reserving transaction. No INTERNAL
error was reintroduced. Regressions: after a clean detach, an invalid async recovery is refused and
the binding, generation and activation history are byte-for-byte unchanged; on a database whose
`schema_version` is 4, an invalid async request leaves it at 4; a valid operation after a clean
detach still adopts the connection and succeeds.

**R10-03 — the binding names its own database.** `assertProbeUsable` now compares
`C.database_path` with the database actually requested and refuses a mismatch with
`database_bound_elsewhere`, which catches the coordinator's reproduction: a copy of `bridge.db`
inside the *same* worktree with the marker removed. The owner record's `database` field is checked
against the binding for the same reason. Regression: the copy is refused, its bytes are unchanged,
no `.owner` file is invented for it, no marker is recreated — and the ordinary
missing-marker-with-matching-binding recovery still completes and republishes `bound`.

**R10-04 — delivery evidence.** Handled above and in the structured report: real distinct
snapshots captured before their runs, paths cited, test identity recorded, and
`verification_results` restricted to final-snapshot checks with the failing historical run kept in
`reproduction_results` only.

## Limitations

1. The manifest records `worktree_dirty: true` for the coordinator snapshot listed above.
2. Marker repair at the async boundary is skipped when authority changed in between; the markers
   then stay incomplete until the next authorized mutation, which status reports.
3. A database copy is detected by the binding it carries; two databases that never carried a
   binding remain indistinguishable, which is why unbound legacy state is fail-closed.
4. All adapters and host envelopes in tests are synthetic fixtures; no live two-model pilot is
   claimed, and the contract's documented limits still stand.
