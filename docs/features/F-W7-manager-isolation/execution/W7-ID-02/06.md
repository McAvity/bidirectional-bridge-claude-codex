## What R13-01 required and what was built

**Deterministic namespace.** `feature_exchange.py` gained `workspace_namespace()`: the key is
`ws_` plus the first 16 hex characters of `SHA-256(canonical worktree root + NUL + canonical
per-worktree git dir)` — the same identity the bridge already uses for workspace state, so a
package namespace and a database binding can never disagree about which worktree they belong to.
It is never the branch, the shared git-common-dir, the feature id or a session id. The layout is
`~/tmp/bridge-exchange/<key>/` with `packages/`, `incoming/` and `staging/`. For this worktree the
key resolves to `ws_<historical-worktree-hash>`, matching the value the coordinator computed independently
before delegating.

**Read-only selection.** The new `namespace` subcommand prints the resolved paths and creates
nothing; resolution claims no ownership and writes no bridge state. The namespace isolates
accidental collisions between concurrent worktrees — it is not an authorization boundary, and the
documentation says so in those words.

**Canonical options, literal overrides.** `export --name <file>.zip` places the archive in the
namespace's `packages/`, and `inspect-return --stage-name <name>` stages under `staging/`. Exactly
one of `--output`/`--name` and one of `--staging`/`--stage-name` must be given, so an agent never
hand-rolls identity by accident. An explicit `--output`/`--staging` is still used **literally**,
unchanged from before, and exclusive creation still refuses an existing target. A namespace path
that would resolve inside the repository fails with a clear message.

**Instructions.** The policy is stated once in `.agents/skills/feature-exchange/SKILL.md` and
referenced consistently from `.agents/skills/feature-execute/SKILL.md`, its `bridge-loop.md`
round-contract section, both byte-identical `using-bridge` mirrors, `docs/features/README.md`,
`docs/feature-workflow.md`, `docs/manager-identity.md` and contract §13. Earlier flat
`~/tmp/<feature>-<purpose>-<n>.zip` examples are marked as historical record rather than rewritten;
no archive was moved or renamed.

## Limitations

1. The namespace prevents accidental collisions between worktrees; it is not access control, and
   any local process may still write into another namespace directly.
2. Historical archives stay where they were written, under the old flat convention. Nothing was
   relocated, and a future move of this worktree changes its key, which by design gives a new
   namespace rather than migrating the old one.
3. `--output`/`--staging` remain literal, so a caller can still place an artifact outside the
   namespace or inside the repository; only namespace-derived paths are checked for that.
4. The key depends on `git rev-parse --path-format=absolute`, i.e. git ≥ 2.31, consistent with the
   rest of the identity implementation.
