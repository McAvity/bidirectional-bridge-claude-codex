## Finding-by-finding

**R14-01 — `--repo` now selects the actual worktree.** `git()` inherited the full process
environment, and `verify` ran one more `git` child directly, so inherited `GIT_DIR`,
`GIT_WORK_TREE` and friends redirected repository selection for every exchange subprocess. The
helper now builds its child environment through `git_env()`, which drops `GIT_DIR`,
`GIT_WORK_TREE`, `GIT_COMMON_DIR`, `GIT_INDEX_FILE`, `GIT_OBJECT_DIRECTORY`,
`GIT_ALTERNATE_OBJECT_DIRECTORIES` and `GIT_NAMESPACE`; both subprocess call sites use it, so
namespace resolution, export and verify agree. The list mirrors the neutralisation the product's
`resolveWorkspaceIdentity` already performs, which I inspected without changing product code.
The regression stands in worktree **A**, asks for **B** with a polluted environment, and asserts
that the key, the namespace directory, the recorded range **and the archived content**
(`exchange/code/src/app.py` carrying B's `VALUE = 99`) all come from B, and that verification
succeeds both under the same pollution and with a clean environment. Explicit `--output`/
`--staging` semantics are untouched.

**R14-02 — live commands use the current namespace.** The Export, Verify and Import examples in
`.agents/skills/feature-exchange/SKILL.md` still prescribed flat `$HOME/tmp` paths with
`--output`/`--staging`; following them recreated the very collision round 8 removed. Export now
shows `--name`, Import shows `--stage-name` with `<namespace>/packages` and `<namespace>/incoming`
sources, and Verify resolves the package from the namespace (noting that the export command prints
the path it wrote, which is the simplest thing to pass back). Each example states that an explicit
literal `--output`/`--staging` is a deliberate override rather than the normal convention. No flat
`$HOME/tmp` path remains in any live instruction, and the executor skill and `bridge-loop.md`
round-contract text already agreed from round 8. Historical ledgers, reviews and archives are
unchanged.

**Small related items.**
- `unittest.main()` moved to the end of `tests/test_feature_exchange.py`, so direct execution now
  runs `NamespaceCase` too: 29 tests by discovery and 29 by direct invocation.
- Targeted guard coverage added: a namespace that would resolve inside the repository is refused,
  and the pre-existing refusal of an explicit `--staging` inside the repository still holds.
- Staging separation is now proved with a **changed** returned document rather than an empty
  report: each worktree stages one real edit under the same `--stage-name`, the two staging
  directories differ, and neither repository is modified.

**Correction to ledger 06 (not a rewrite of it).** Ledger 06 limitation 3 said a caller could
"still place an artifact outside the namespace or inside the repository" with explicit paths. That
is imprecise: an explicit `--staging` inside the repository has always been rejected by the
existing guard, and an explicit `--output` is rejected only when it points inside the feature
directory. So the accurate statement is: explicit `--output` may still write elsewhere in the
repository outside the feature directory; explicit `--staging` may not write into the repository at
all. Ledger 06 is left exactly as written.
