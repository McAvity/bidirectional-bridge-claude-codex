## Integration regression found and fixed inside this round

Making `result()` pure initially left the **stored** feature record unreconciled after a completed
round. The operator dry run reads that persisted state, so
`python3 -m unittest discover -s tools/pilot/tests` went from 110 passing to **1 failure**
(`test_portable.DryRun.test_tooling_dry_run_scores_every_criterion`, refused with
`feature state in ('awaiting_review',)` because the row still said `running`). I did not touch the
operator tooling; instead I used the path review 11 explicitly allows — "reconcile in guarded
reservations **or explicitly trusted worker completion paths**".

`run()` now reconciles once, after its own worker returns, inside a transaction that first
re-runs the request's authority guard: if the session was fenced or taken over in the meantime the
write is skipped and the next authorized call reconciles instead. Responses still derive. After
this correction the pilot suite is back to 110 passing, and a new regression pins the behaviour
downstream depends on (stored state is `awaiting_review` with no active task after a normal round)
so it cannot silently regress again.

## Finding-by-finding

**R11-01 — round responses derive, never reconcile.** `FeatureWorkflow.result()` called the
mutating `get()`/`refresh()`, so both an idempotent replay and the response returned after a
long-running worker wrote the feature row and a `FEATURE_UPDATED` event outside any guard — a
replay from a fresh instance after a clean detach has only the pure precheck and no activation
transaction, so the write happened with no authority transaction at all. `result()` now builds its
response from the pure `view()`; persistence stays in the guarded reservations that already call
`refresh` (`run`'s reservation via `onTaskCreated`, `waitUser`, `answerUser`, `accept`). The
derived answer is unchanged for the caller, so no behaviour was weakened. Regressions: a stale
stored `running` feature whose round task is `DONE`, replayed from a fresh same-thread instance
after a clean detach — the response correctly derives `awaiting_review` while the stored feature
rows, `lastEventId` and activation history are byte-for-byte unchanged and the fixture adapter is
started only once; and a response produced after a takeover, where the stored record stays
`running` (no request-side write) while both the response and a pure read derive
`awaiting_review`; and a normal round, where the trusted completion path does persist
`awaiting_review`.

**R11-02 — contradictory nonces are refused in every state.** `assertProbeUsable` compared the
reservation nonce with the binding only when the record claimed `bound`, so a `reserving` record
carrying a *different* nonce was accepted and then repaired — inferring an interrupted publication
from what the contract classifies as contradictory state (§4.1/§4.5). The comparison is now
state-independent for the marker and for the owner record separately, and the message names the
state it found. What remains recoverable is exactly what the contract allows: a `reserving` record
with the binding's own nonce, and an absent record reconstructed from the binding. Regressions
cover the marker and the owner mismatch separately — each refused with
`unresolved_workspace_state` and with the contradictory file left byte-identical — plus the
preserved same-nonce repair and missing-record reconstruction.

## Limitations

1. Feature state is persisted by the trusted worker-completion path of the round that produced it;
   a replay, or a completion whose session was fenced meanwhile, leaves the stored record stale
   until the next authorized call. `bridge_feature_get` and the round response both derive the
   correct state regardless, and `bridge_manager_status` still reports recovery needs.
2. Contradictory marker/owner state is refused, not repaired: resolving it needs operator
   inspection, which is the contract's intent.
3. All adapters and host envelopes in the tests are synthetic fixtures; no live two-model pilot is
   claimed, and the contract's documented limits (host 0.154.0, local advisory locking, no defence
   against a forged same-UID envelope) stand.
