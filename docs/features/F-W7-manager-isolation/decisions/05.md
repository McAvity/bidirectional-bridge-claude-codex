## Plan weryfikacji i kryteria odbioru

1. Ustalić wersję lokalnego Codexa i pochodzenie dostępnych źródeł; prześledzić uruchomienie stdio MCP i initialize, bez wnioskowania z samego shell env.
2. Sprawdzić tylko obecność konkretnych pól w działającym MCP, bez publikowania uchwytów/sekretów. Prześledzić tworzenie/resume/fork thread_id i session_id oraz guardian.
3. Zbadać automatyczny kanał startowy oraz minimalny launcher. W miarę możliwości wykonać odizolowany test protokołu bez wywołania modelu; wyraźnie rozdzielić test binarki, analizę kodu i projekt rozwiązania.
4. Raport ma wskazać pochodzenie ID, zachowanie po resume, separację równoległych sesji i guardiana, granicę zaufania, brakujące dowody i konkretny następny krok. Nie uznać propozycji launchera za wdrożone rozwiązanie.

Dozwolony zakres teraz: odczyt i kontrolowane próby tożsamości, raport/evidence oraz checkpoint koordynatora. Przypięty runtime i kontrakt bez zmian. Bez nowej próby Claude’a w tym kroku; zakończony task i sesja zachowane. Przy dalszym wykonaniu właściwy lifecycle dla DONE, nie recovery DONE ani sesja zastępcza.
