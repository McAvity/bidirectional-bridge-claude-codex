## Faktycznie zatwierdzona zmiana

Granica gwarancji: ochrona przed przypadkowym pomieszaniem poprawnie działających lokalnych sesji; bez odporności na złośliwy proces tego samego UID. Dokładny natywny thread managera pozostaje wymagany. Preferowane źródło: params._meta.threadId z kontekstu requestu MCP, nadane przez host Codex, nigdy args modelu. Brak ręcznego przechowywania tokenów.

Dotychczasowy kierunek wiązania przy starcie MCP zastępuje badany kierunek pierwszego wywołania wymagającego własności. Handshake, tools/list oraz odczyty nie mogą przypisywać/przejmować worktree. Wykonawca ma najpierw sprawdzić wykonalność, w tym guardian; jeżeli wykonalne, poprawić kontrakt. Hook/launcher wolno proponować tylko z dowodem, dlaczego wariant podczas wywołania jest niewystarczający, nie jako automatyczny dodatek. Nie wolno ukryć luki przez uznanie każdego pierwszego thread za uprawnionego managera.

## Zakres korekt i plan

Claude kontynuuje W7-ID-01 w tej samej przypiętej sesji featura. Dotychczasowa runda ma DONE, więc prawidłowa jest kolejna runda feature_run, nie recovery DONE ani sesja zastępcza. Budżet rundy 75 minut / 200 tur; bez retry po timeout bez decyzji użytkownika. Polling co 5 minut. Lokalne commity oraz export/verify paczki w zakresie rundy są autoryzowane.

1. R03-01: zbadać first-ownership-call binding i zapisać jednoznaczny protokół wraz z rzeczywistą granicą gwarancji. Natywny ID bierze immutable per-request context, nie globalny last-call context. Wyjaśnić, jak guardian/auto-review nie może zostać pierwszym właścicielem. Sam różny threadId wystarcza do odrzucenia guardiana po bindingu, ale nie dowodzi jego nieuprawnienia przed bindingiem; potrzebne konkretne dowody klasyfikacji/ograniczenia hosta lub jawne stwierdzenie brakującego kanału.
2. Atomowe pierwsze przypisanie wraz z uprawnioną operacją, bez częściowego przejęcia po błędzie walidacji. Równoczesne pierwsze wywołania mają jednego zwycięzcę. Każda następna mutacja i recovery sprawdza natywny ID i aktualną instancję/epoch w tej samej transakcyjnej granicy co zapis. Brak/obce/złego typu ID odrzuca przed mutacją; args nie są fallbackiem. Określić też role Claude i trusted internal worker tak, aby nie wymagały nieistniejących metadanych Codexa ani nie omijały istniejącej lineage.
3. Resume tego samego natywnego thread zachowuje trwałe powiązanie; określić restart MCP i dwa jednoczesne resume/instancje tego samego ID bez fencing ping-pong. Nowa sesja wymaga jawnego takeover z kontrolą poprzedniego bindingu/epoch, powodem, historią i bez cichego restartu wykonawcy. Stara sesja po takeover nie może ponownie przejąć przez zwykły mutator. Brak tokenów custody.
4. R03-02: spójnie oddzielić odczyt od reconcile/reap/migracji. Nie przejmować ani modyfikować worktree przez start/odczyt. Rozliczyć rzeczywiste zapisy konstruktora SqliteStateStore (DDL/schema_meta/journal), nie tylko recover; init/migracje dopiero w autoryzowanej ścieżce. Podać konkretną granicę transakcji guard+mutation.
5. R03-03: jeden atomowo zarezerwowany wybór DB dla worktree, także dwa procesy/jeden worktree/dwa --db i dwa worktree/jeden --db. Rozliczyć A/B/C, brak A/B, zewnętrzny sidecar, awarie w połowie bootstrap oraz fail-closed bez fałszywej obietnicy odbudowy.
6. R03-04: archiwizacja poza repo i ograniczenie zewnętrznego DB; bez instalatora/diagnose/rebind produktu.
7. Usunąć z AKTUALNEJ rewizji kontraktu nieaktualne twierdzenia no-native-source/advisory-only/manual-token i sprzeczne warianty; historyczne ledgery/reviews/decisions pozostają nietknięte.
