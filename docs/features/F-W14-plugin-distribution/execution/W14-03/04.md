## Disposition

### W14-R2-07, boundary before the first `.bridge-runtime` write

**Reproduced** at `f3bba25…`: a SIGKILL at the first `.bridge-runtime` creation leaves the runtime's
own `.bridge/workspace.json` and no selection directory; the restart refused, and the following
authorised mutation never reached a server.

**Fixed.** That marker is the runtime's own record of which worktree the state belongs to, so it is
already the authority for "explained and mine". `classifyNativeState` reads it — read-only, no
database opened — and classifies `absent | own | foreign | unexplained`. A worktree with an `own`
reservation and no selection directory serves reads and is completed by the next authorised
mutation. `foreign` and `unexplained` stay refused, with the bytes untouched.

### W14-R2-07, boundary after the record write

**Reproduced:** `CRASH_AFTER=2` leaves `pending.json` because the record is written before the
journal is removed; a later successful mutation left it behind forever, since `decide` reported
`resuming=false` for a valid record and the materialiser returned early on one.

**Fixed.** An own unfinished journal is work to complete even when the record is valid. Both the
gate and the materialiser now say so, and `planChange` picks it up as `plan.pending` exactly as the
CLI does. Completion still happens only after authorisation.

### W14-R2-09 — default rollback selected the current runtime

**Reproduced:** after a real `update`, `rollback --yes` refused `ROLLBACK_SAME_RUNTIME` naming the
runtime it was meant to leave — the resolver treated rollback like setup and read the declared pin.

**Fixed** by extracting the wave12 CLI's history-based `rollbackTarget` into
`scripts/setup/workspace.mjs` and sharing it verbatim, so the CLI and the plugin resolve identically.
The default now returns the declaration *and* the local selection to the previous runtime, the
database is preserved, an explicit `--to` still wins, a worktree with no history refuses
`ROLLBACK_NO_PREVIOUS`, and rollback refuses `ACTIVE_SESSION` while a server is serving. Rolling
back twice moves forward again: that is the wave12 resolver's own "previous distinct entry"
semantics, kept rather than redefined, and it is recorded as a limit.
