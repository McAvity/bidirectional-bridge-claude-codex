## Problems and resolutions

Facts established by the probes (Git 2.43.0) that shaped the contract:

- `git clean -ndX` in the parent *skips* nested repositories but would delete loose files in the
  task directory; `-nffdX` would delete the whole `.feature-repos/`. My first assertion assumed
  single `-f` removes the task directory; corrected to the observed behaviour. Contract § 2.7:
  task directory holds only checkouts, checkpoints stay in the exchange namespace.
- O1 confirmed: plain `git worktree remove <parent>` succeeds and deletes the ignored task
  directory; an in-parent clone's unintegrated commit is lost, a nested worktree's commit survives
  in the source (metadata becomes `prunable`), its uncommitted file is lost.
- O2 confirmed: commits in a nested worktree add objects/refs and `worktrees/<name>/` in the
  source gitdir outside the parent; a clone keeps them inside.
- P06: in a linked parent, the submodule gitdir is
  `<common>/worktrees/<wt>/modules/<path>`; `submodule update --init` writes url/active into the
  common config; the main checkout stays unpopulated and clean.
- Read-only dependency writes into an ignored `dist/` are invisible to plain `git status`; the
  contract uses an `--ignored=matching` digest.
- Runner: a mid-path wildcard scope widens `--add-dir` to the literal prefix; alias text is passed
  unresolved; `normalizePath` strips a leading `/` silently. Contract requires literal per-repo
  prefixes and no absolute scope.
- My first worst-case header bound (1200 chars) was arbitrary; measured 1535, bound set to 1600,
  well under the 4000-char stored summary.

Probe scratch directories created during exploration were removed; every test fixture is a fresh
temporary directory deleted in teardown.
