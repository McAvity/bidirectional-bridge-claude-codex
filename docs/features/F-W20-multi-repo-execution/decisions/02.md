## Proponowany zakres

Cały W20-01…03: kontrakt i próby wykonalności → wspólna procedura oraz odczytowy
helper → podłączenie koordynatora/wykonawcy i pozostałych skilli → paczki,
syntetyczne scenariusze i dokumentacja → integracja, niezależne lokalne review,
niezbędne poprawki w zakresie briefu i lokalne commity. Astra koordynuje, Claude
implementuje przez bridge. W20-01 ma lokalną bramkę techniczną, nie dodatkową
bramkę użytkownika po tasku. F-W19 nie jest zależnością wykonania.

Weryfikacja: rzeczywiste tymczasowe repo Git dla izolacji/receipt/resume/partial merge,
testy argv i transportu dostawy, scenariusze instrukcji, spójność paczek, build,
testy JS/Python/pilot-tooling z AGENTS i dokumentacja. Nie używamy realnych danych
ani repo child użytkownika. Brak pilota modeli nowej funkcji w proponowanym zakresie;
nie deklarujemy dowodu samodzielnego zachowania modeli z syntetycznych testów.
Zewnętrzny alias z niepotwierdzonym dostępem nie jest ścieżką zaliczoną; istnieje
wariant fizycznego checkoutu/klonu lokalnego i jawna blokada hosta, jeśli potrzebna.
Niezależne review i wykonanie przez Claude to część pracy nad feature, nie taki pilot.

Bez merge, push, publikacji, upgrade realnych projektów, zmian osobistych profili,
rebuild aktywnego runtime, tworzenia parent worktree za użytkownika lub nowego MCP.
Właściwy typ późniejszego wydania zależy od dostawy F-W19: obecnie bridge release,
po niezależnym wersjonowaniu zgodny workflow-only. Nie wykonujemy publikacji teraz.
Rzeczywista potrzeba zmiany silnika zamiast wykonalnego wariantu instrukcji wymaga
checkpointu wpływu; nie rozszerzamy niejawnie zakresu.

## Pytanie oczekujące

Czy zatwierdzasz wykonanie całego W20-01…03 według tego planu, wraz z integracją,
niezależnym review, poprawkami i lokalnymi commitami, bez publikacji i upgrade projektów?

Po zgodzie feature-decide zapisuje nową decyzję z rzeczywistą odpowiedzią,
a feature-flow przechodzi do feature-execute bez ponownego Gate 1 po taskach.
Końcowy odbiór użytkownika pozostaje osobnym Gate 2. Bez bridge featura F-W20:
pytanie jest w tej decyzji i indeksie; nie tworzymy featura/workerów tylko dla pytania.
