## Problem

`noresult` mode of `claude/claude-side/test/fixtures/fake-claude-cli.mjs` writes
`FAKE_CLAUDE_STDERR` and then calls `process.exit(3)`. On macOS, Node pipe writes to
stdout/stderr are asynchronous; `process.exit()` discards queued data. Only the first
65 536 bytes (the pipe buffer) arrived. The old comment stated the Linux-only assumption
("Pipes are synchronous on Linux").

## Diagnosis (before change)

- Direct: payload `"x"*99992+"TAIL-MARK"` (100 001 bytes) → rc 3, stderr 65 536 bytes,
  no `TAIL-MARK`.
- Through runner: `claude-code-runner.evidence.test.ts` › "bounds the in-memory stderr tail but
  counts every byte" failed with `expected 65536 to be 100001` (`stderr.total_bytes`).
  Reproduced at base in 8/8 full-file runs.

## Change

`fake-claude-cli.mjs` only:
- `noresult`: `process.exit(3)` → `process.exitCode = 3`. Nothing else keeps the event loop
  alive in that mode, so the process exits with code 3 after stdout/stderr drain.
- Updated the stderr comment to the platform-correct reason.

Other modes are untouched (`hang` still keeps an interval; the remaining modes already exit
naturally). Exit code 3 and init-only stdout framing are preserved (check 2 asserts both).
No new test assertion: the existing evidence test already asserts exact `total_bytes`, tail
bound and `TAIL-MARK`, and it now serves as the regression test (it failed before, passes after).
`claude-code-runner.evidence.test.ts` is unchanged.
