## Limitations

1. **No model, no pilot, no CI.** Real CLI, real launcher, synthetic executor. Not real-agent
   evidence, and this delivery is not acceptance.
2. **A real `ENOSPC` device is not created.** `RLIMIT_FSIZE` produces the same short write and
   `EFBIG` from `write(2)`; the defect it exposed (a truncated package published as complete) was
   real and is fixed. A filesystem that fills mid-`fsync` is still untested.
3. **Rotation during an export** is proven as *detection of a file that changed under the reader*
   with a concurrent appender; not every interleaving of a real retention pass is covered.
4. **Leftover private staging after a hard kill** is possible by design: the killed process
   cannot clean up. Nothing reads it, and the documentation says how to remove it.
5. **Closed vocabularies** mean a package produced by a newer runtime reports an unknown state or
   code as `"invalid"`. Deliberate, documented, and the raw value stays in the worktree's log.
6. **Interleaving the database and the log remains an approximation**: two cutoffs, two clocks.
7. **`--with-database` still carries everything**, including free text. Explicit extension.
8. Integration into `feature-workflow`, CI, independent re-review and user acceptance are outside
   this round.
