## Finding by finding

### R2-01 — private content reached the minimal package — **resolved**

One boundary now, in `scripts/diagnostics/project.mjs`: every part of a package — records, log
details, event payloads, evidence metadata, versions, doctor checks, gaps and the manifest — goes
through `projectRecord(record, spec)`.

- **Keys are allowlisted per part.** `LOG_DETAIL_SPEC` is the list the runtime actually writes,
  not "any scalar with a tidy key name"; what was dropped is a count, never a name or a value.
- **Values are typed**, and the types that read the diagnosed state are **closed vocabularies**:
  task and feature states, deliverable statuses, attempt outcomes, error codes, termination kinds,
  phases, log ops and events, agents, journal modes, recovery modes, tool names, event types,
  errnos and shutdown reasons. A value outside its domain is written as the constant `"invalid"`.
  This is what the review's own reproduction needed: a shape rule alone cannot tell a bridge error
  code from `REVIEW_PRIVATE_ANSWER_731`, and the sentinel was planted in an allowlisted key
  (`details.reason`).
- **Errors are codes.** `JSON.parse` failures become `unparsable`; a gap carries a part, a reason,
  an errno-style code, a bridge-generated file name and a count — nothing that quotes input.
- Null and absent fields are omitted, which also made packages about four times smaller.

Regression: `R2-01: no unknown detail, no parser message and no free text reach a default
package` plants sentinels in `details.prompt`, `details.answer`, `details.message` and
`details.reason`, in a malformed event payload and in a corrupt `install.json`, then asserts the
whole package contains none of them, that the planted record survives as
`{deadline_ms, reason: "invalid", dropped_fields: 3}`, and that every gap has only machine fields.

Related honesty fix inside W13-01's own contract: `callCorrelation` recorded `args.to` as
`target_agent` for every tool, so `bridge_set_state` logged the target **state** as an agent. It
is now recorded only for `bridge_delegate`.

### R2-02 — incomplete filesystem and output boundaries — **resolved**

New `scripts/diagnostics/safe-read.mjs` is the single read boundary: every path component below
the worktree is `lstat`-checked, the final component is opened with `O_NOFOLLOW`, only regular
files are read, and every read returns the identity of what it read. The database (default or
`--db`), the log directory, the evidence directory and each task directory all go through it.

Publication: the package is written in a private `0700` staging directory and **linked** into
`packages/`. `link` is atomic and fails with `EEXIST`, so the check-then-rename race the review
found cannot overwrite a package that appeared in between. The namespace itself is checked for
links before anything is created. The namespace resolver is no longer duplicated: it now lives
once in `shared/control-plane/src/workspace-identity.ts` as `exchangeNamespace`, and a Python test
asserts it agrees with `feature_exchange.py namespace` on a real worktree.

Interface: `--out` and `--name` are **removed** rather than validated — the plan's interface is a
scope and a package in the namespace, and the review allows dropping the extra selectors. What
remains is `--feature | --task [--attempt] | --since`, plus `--db`, the two extensions and
`--inspect`.

Regressions: `R2-02: directory links, a linked database and output links are refused, not
followed` (logs → outside directory, evidence → outside directory, database → outside file,
packages → outside directory; each refused or skipped, the outside files unchanged, the removed
flags rejected) and `R2-02: a published package is never overwritten, even by a same-named late
arrival` (`publishPackage` on an occupied name refuses and leaves the existing bytes).

### R2-03 — the selected scope did not cover every source — **resolved**

`resolveScope` computes one scope from the snapshot and every source uses it: tasks, attempts,
telemetry, events, evidence files and log records. `--attempt` filters all of them. A named
feature or task that does not exist is `DIAGNOSE_SCOPE_NOT_FOUND`, not a silent widening;
`--feature` with `--task`, `--attempt` without `--task`, a negative attempt and an unparsable
`--since` are `DIAGNOSE_SCOPE_INVALID`. A window selects the tasks it touched, up to
`MAX_WINDOW_TASKS`, and reaching that bound is reported in the manifest and as a gap. Process-level
log records are kept only inside the incident's own time span, so they are context, not history.

Regression: `R2-03: one scope covers every source, and an unknown selector is refused` builds a
second attempt (rows, telemetry, evidence, log record) and a second unrelated incident, then
asserts attempts/telemetry/evidence/log records are all attempt 0 only, that the foreign task
appears nowhere, and that each invalid or unknown selector is refused.

### R2-04 — diagnose executed code the diagnosed worktree selected — **resolved**

The collector resolves identity through `loadControlPlane(ownRoot, cliRuntime)` — this CLI's own
build, or the runtime this CLI was installed in — and never through `.bridge-runtime/current` of
the worktree. `runDoctor({ safeSubset: true })` does the same, and its exchange-namespace probe
now runs this CLI's own copy of `feature_exchange.py`, or nothing at all in the safe subset. The
worktree's selection is read as data: its manifest is parsed for `versions.runtime`, and no file
of it is imported. `versions.collector.source` records `own-build` in every package.

Regression: `R2-04: a runtime chosen by the diagnosed worktree is never executed` installs a
synthetic runtime whose `control-plane/dist/index.js` writes a marker on import, points
`.bridge-runtime/current` at it, and asserts the marker never appears while summary, package and
doctor subset all run — and that the package still describes that runtime from its manifest.

### R2-05 — read boundaries and gaps were reported imprecisely — **resolved**

Logs are read as a bounded prefix through a descriptor (`readBounded`, 1 MiB from the end), not by
reading the whole file and trimming afterwards. `cutoffs.logs.files[]` now carries, per file: size,
`bytes_read`, `read_from`, `truncated`, inode, modification time, `partial_last_line` and
`changed_during_export`. `read_at` is taken when the logs are read, after the snapshot. A bounded
prefix that starts mid-record drops that fragment and reports `logs:prefix_truncated`. Record
limits are reported in `cutoffs.records` and as a `record_limit` gap instead of a silent
`slice`. After the package is assembled, every log file's identity is re-checked: a rotation,
truncation or deletion during the export becomes `logs:changed_during_export` or
`logs:removed_during_export`.

Regressions: `R2-05: reads are bounded per file and every limit, truncation and change is
reported` (a log grown past the bound; then a concurrent appender during the export, asserting the
change is detected) and `R2-05: a record limit is reported instead of silently dropping the rest`
(5 200 events → 5 000 in the package, the limit in `cutoffs.records` and in a gap).

### R2-06 — the matrix called unexecuted scenarios PASS — **resolved**

Three real scenarios replace the three claims:

- **Interruption**: the CLI is `SIGKILL`ed while its private staging directory exists. Nothing is
  published, the source fingerprint is unchanged, and the next export succeeds. Leftover staging
  after a hard kill is documented rather than claimed away.
- **A write that cannot complete**: the export runs under `ulimit -f 20`. This uncovered a real
  defect — `writeSync` answers a file-size limit (and a full disk) with a **short write**, not an
  exception, so the previous single-call writer would have published a truncated package that
  still looked complete. `writeZip` now loops, proves the size on the descriptor and raises
  `ESHORTWRITE`; the export refuses with `DIAGNOSE_OUTPUT_UNWRITABLE` and publishes nothing.
- **Hard-stopped worker**: the launcher is `SIGKILL`ed, and the package shows the absent
  `process.stop`/`log.close` records and the stale active marker as the gap they are.

The corrected acceptance matrix, with what is still not simulated, is in the
[W13-03 ledger](../W13-03/02.md).

## Limitations

1. Model-free evidence only: the real CLI, the real launcher and the repository's synthetic
   executor. No real-agent claim, no pilot, no CI.
2. `ENOSPC` itself is still not produced: `RLIMIT_FSIZE` yields `EFBIG` from the same `write(2)`
   path, and the short-write behaviour it exposed is the one a full disk takes. A true
   out-of-space device needs a mount this test environment cannot create.
3. The rotation-during-export regression drives a concurrent appender; it proves detection of a
   file that changed under the reader, not every interleaving a real rotation can produce.
4. A closed vocabulary means a package produced by a **newer** runtime with a new state or code
   reports that value as `"invalid"`. That is deliberate and documented, and the raw value is
   still in the worktree's own log.
5. `--with-database` still carries every field the bridge stores, including free text. It is an
   explicit extension, named in the manifest and the risk note.
6. Leftover private staging after a hard kill is possible; the export never reads it, and the
   documentation says how to remove it.
