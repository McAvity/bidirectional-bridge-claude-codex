## R2-02 (remaining) — the namespace was trusted — **resolved**

**Cause.** `assertUnderRoot(namespace.namespace, …)` never inspects its own anchor, and the two
recursive `mkdir` calls ran *before* it. A namespace directory that is a symlink therefore had
`packages/` and `staging/` created inside whatever it pointed at — the review reproduced exactly
that, with no race involved.

**Fix.** `safe-read.mjs` gained `assertSafeDescent(anchor, target)`: it walks every component below
a trusted anchor, refuses a symlink or a non-directory, and stops at the first component that does
not exist yet — so it can run *before* anything is created, which is the whole point.
`assertUnderRoot` is now that walk plus "must already exist", so there is one rule, not two.

- **Output.** The anchor is the home the namespace was derived from. The namespace directory,
  `packages/`, `staging/` and this run's private staging directory are all walked **before** the
  first `mkdir`; a link anywhere on that path refuses with `DIAGNOSE_OUTPUT_UNSAFE` and nothing is
  created. The atomic no-overwrite publication (`link` into `packages/`, then unlink the working
  copy) is unchanged.
- **Sources.** The same skipped-root pattern existed below `.bridge`: the logs and the evidence
  were anchored *at* `.bridge`, so that component itself was only checked as a side effect of the
  database path — and not at all when the database was absent or `--db` pointed elsewhere. The
  state directory is now checked once from the worktree root before any source is read, and the
  log and evidence walks are anchored at the worktree root (at the external database's parent for
  `--db`). A missing database is still a normal gap; a redirected one is a refusal.

**Regressions.** `R2-02: a linked namespace, staging or packages is refused before anything is
created` drives the review's four shapes — the namespace itself, `staging` with an absent child,
`packages` with an absent child, and an ancestor of the namespace — and asserts
`DIAGNOSE_OUTPUT_UNSAFE` plus an outside directory that still contains exactly its own file.
`R2-02: a linked state directory is refused even when the database is absent or external` moves
the database out, replaces `.bridge` with a link, and asserts `DIAGNOSE_PATH_UNSAFE` both without
`--db` and with it, with nothing published and the outside logs unread.

## R2-05 — actual rotation during an export — **resolved**

**Fix (test, not product).** The detection added in round 3 was right; the evidence was an append,
which is not a rotation. Deterministic timing without a product hook: the export reads the logs,
then asks doctor for its safe subset, which runs `codex --version`. A stand-in `codex` on `PATH`
performs the rotation at exactly that moment — after the read, before the final identity check.

**Regression.** `R2-05: a log renamed, replaced or unlinked during the export is reported as such`
runs all three shapes: `rename` and `unlink` produce `logs:removed_during_export`, a rename
followed by a fresh file at the old name produces `logs:changed_during_export`, each naming the
file; `cutoffs.logs.files[].changed_during_export` is `true`; the records already read stay in the
package as the prefix of the inode they came from; and the rotated file the worktree itself made
is untouched by the export.

## R2-06 — deterministic `ENOSPC` — **resolved**

**Fix.** `writeZip` takes its two write primitives from an injectable `REAL_IO` pair (`write`,
`fsync`), and `runDiagnose` forwards an optional `io`. The default is the real filesystem; this is
the fault-injection point the review allows, and it is one optional parameter rather than new
architecture.

**Regression.** `R2-06: a disk that fills mid-package, or fails on fsync, publishes nothing` runs
both shapes the review named: a short write **after real progress** (1 KiB written, then `ENOSPC`)
and a clean write that fails on `fsync`. Each asserts `DIAGNOSE_OUTPUT_UNWRITABLE` carrying
`ENOSPC`, an empty `packages/`, no leftover staging, a byte-identical worktree fingerprint, and a
normal export from the same worktree once the device recovers. The `RLIMIT_FSIZE` test from round
3 is kept as separate evidence of the same branch reached through a real kernel limit.

## Limitations

1. Model-free evidence only; no real-agent claim, no pilot, no CI.
2. `ENOSPC` is injected at the write primitives, not produced by a full device: a mount this
   environment cannot create. The injection reproduces both shapes a full disk takes (a short
   write after progress, and a failing flush), and `RLIMIT_FSIZE` still exercises the same branch
   through the kernel.
3. The rotation evidence uses doctor's own subprocess as the sync point. It proves detection of a
   file renamed, replaced or unlinked between the read and the final check; it does not enumerate
   every interleaving a concurrent retention pass can produce.
4. The namespace anchor is the home the namespace was derived from. A home that is itself a
   symlink is the user's own arrangement and is not second-guessed; everything below it is checked.
5. A hard kill can still leave a private staging directory; nothing reads it, and the
   documentation says how to remove it.
