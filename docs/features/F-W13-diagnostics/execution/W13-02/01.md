## What was built

`scripts/diagnostics/`, three modules, plus the `diagnose` command in `scripts/bridge.mjs`:

- **`zip.mjs`** — a stored-only ZIP writer and a strict reader. No dependency the setup CLI does
  not already have; entry names that could escape a directory are refused before anything is
  written, and `wx` means a package is never written over an existing file.
- **`project.mjs`** — the privacy projection: a fixed field list per record type (tasks,
  attempts, telemetry, events, log records, doctor checks), scalar-only values, known credential
  shapes replaced, and absolute paths replaced by package-local aliases (`<workspace>`,
  `<home>`, `<path-N>`) whose map is never written into the package.
- **`collect.mjs`** — scope resolution, the snapshot, the collection and the package.

Order of operations, and why each step is where it is:

1. **Resolve the worktree with the existing resolver** — the selection's runtime, else the CLI's
   runtime, else this checkout. Nothing new identifies a worktree.
2. **Private snapshot through SQLite's backup API** into a `0700` staging directory inside the
   worktree's exchange namespace, then `journal_mode = DELETE` on the copy so it is one file, and
   `integrity_check` **on the copy**. A live WAL writer is therefore included and the source is
   never copied file by file. The snapshot is deleted at the end unless `--with-database` asked
   for it; it is never in a default package.
3. **Read the selected scope out of the copy** with explicit `SELECT`s. No store, no migration,
   no repair, no claim, no adoption, no recovery, no takeover — and no path found in a row is
   ever opened.
4. **Read this worktree's own logs**: only regular files matching the logger's name pattern, each
   bounded, with the bytes actually read recorded. A symlink in the log directory is reported and
   skipped.
5. **Reuse doctor**, with a new `safeSubset` option that skips the two checks which would start
   something (`handshake`) or load the project's own configuration (`codex_project`). Both are
   reported as skipped and named in `doctor.json.omitted`, so the subset is visible, not implied.
6. **Write the package** into staging first, then `rename` it into `packages/`, so an interrupted
   export leaves no half-written package; the staging directory is removed in a `finally`.

Selection is minimal and non-overlapping: `--feature`, `--task` (+ `--attempt`), `--since`
(`30m`/`6h`/`2d` or ISO). No selector prints what can be selected — features, recent tasks, log
files, database cutoff — and exports nothing. `--db` names a deliberately chosen external
database, `--out` a literal destination, `--inspect` re-checks a package against its own manifest,
and the two extensions are `--with-evidence` and `--with-database`.

## Package contents and honesty about them

`diagnostics-manifest.json` (format `claude-codex-bridge.diagnostics/v1`) carries the scope, both
cutoffs, versions (runtime manifest, selection record, host), counts, the collected file list with
a SHA-256 for every entry, the gaps, the extensions in force, the privacy statement and the
limits. Beside it: `timeline.md`, `records/{tasks,attempts,telemetry,events,feature,workspace}.json`,
`logs/<file>.jsonl`, `evidence/index.json`, `doctor.json` and `ANALYSIS.md`.

Two cutoffs, never one: the database snapshot instant with its last `event_id`, and the log read
instant with the bytes read per file. Processes are not inspected, and the manifest says so
(`cutoffs.processes.observed: false`). The timeline states in its own header that interleaving the
two sources is an approximation, that `seq`/`mono_ms` order one process and `event_id` orders the
database. Anything missing — an absent, unopenable or corrupt database, unparsable log lines,
unreadable evidence, a missing runtime selection — is a `gaps` entry, and a package with gaps is
still produced.

Privacy is an allowlist: prompts, answers, transcripts, objectives, write scopes, verification
criteria, blockers, user questions and answers, and process stderr are simply not collected.
Execution handles and native thread ids appear only as 12-hex digests. The extensions are
explicit, recorded in the manifest and announced in the risk note the command prints; the note
also says plainly that redaction is a guardrail and that the package should be reviewed before
sharing. Nothing is uploaded.

## Doctor diagnostics status (deferred from W13-01)

`doctor` gained a `logs` check: no log at all is `ok` (the runtime writes one after its first
authorized call), a healthy log is summarised with file count, bytes, newest record and what
retention deleted, a logger that reported write failures is `LOGS_DEGRADED`, an unreadable
directory is `LOGS_UNREADABLE`, and a symlinked `.bridge/logs` is `LOGS_PATH_REDIRECTED`. The
three new codes are listed in `docs/setup.md#doctor-codes`, which is what W13-01 could not do
inside its write scope.

## Deviations

1. **ZIP written by hand.** The repository has no archive dependency and the setup CLI must run
   from a fresh clone, so the export writes stored entries itself. The Python interoperability
   test exists precisely because "we can read our own format" would not be evidence.
2. **`--since` accepts `30m`/`6h`/`2d` as well as an ISO instant.** One flag, two spellings, no
   second mode.
3. **A window scope learns its tasks from the window**, so `--since` alone still produces task,
   attempt and evidence records rather than events only.

## Limitations

1. Model-free evidence only: the real CLI, the real launcher and a synthetic executor. No
   real-agent claim, no pilot, no CI.
2. A full disk is not simulated literally; the unwritable-destination and unwritable-log paths
   exercise the same failure branch (`EACCES` instead of `ENOSPC`).
3. The alias map is not written anywhere, so two packages from one worktree cannot be correlated
   by alias; inside one package the correlation holds.
4. `--with-database` includes every field the bridge stores, including the free text the default
   package withholds. That is the point of an explicit extension, and the manifest and the risk
   note say it.
5. Redaction is an allowlist plus known credential shapes: content placed inside an identifier
   (a feature id, a task id) still travels.
6. The export reads `.bridge/logs` and the database of the worktree it is pointed at; it does not
   collect anything about processes, and a refused call that never reached the log is only in the
   stderr of the process that refused it.
